## 0.3.0

- New `bundle` command: compiles the browser entry (`lib/main.client.dart`,
  or `--entry`) to `web/client/main.client.dart.js` (`--output`) with
  `dart compile js -O2 -Djaspr.flags.release=true` and no source maps.
- `dev` keeps the client bundle up to date when the package has a browser
  entry: it builds it (`-O1` with source maps) before serving and after every
  change of a `.dart` file that generates cleanly, in parallel with the hot
  reload. New options `--client-entry` and `--output`; a failed build is
  printed and the previous bundle stays. When `dev` stops, a build in
  flight finishes without printing and no further build starts.
- `bundle --entry` and `dev --client-entry` with a file that does not exist
  fail with exit code 64 and `No <file>.` (the default entry, when missing,
  still means "no bundle" and exits 0). `bundle` exits 73 when a bundle
  file cannot be written and 70 when the compiler cannot be started.
- **Breaking:** `GrundCli(interruption:, keys:)` is now
  `GrundCli(host: CliHost(interruption:, keys:, compileRunner:))`; `CliHost`
  and `CompileRunner` are exported (the seam for tests).
- `init --template fullstack` adds a hydrated counter (`lib/clients.dart`,
  `lib/main.client.dart`, `lib/src/pages/counter.dart`), ignores
  `web/client/` in git and names `grund_jaspr: ^0.3.1` and
  `grund_cli: ^0.3.0`. A project generated by this version requires
  `grund_jaspr` 0.3.1.

## 0.2.0

- **Breaking:** requires Dart 3.13 (`sdk: ^3.13.0`).
- `analyzer` is now `>=13.3.0 <15.0.0` (was `>=8.1.1`): the lowest version that parses Dart 3.13 sources.
- `init` scaffolds name `sdk: ^3.13.0`.
- The `init` templates read `HOST` and `PORT` through `EnvironmentModule` and
  scaffold the new dependency versions.

## 0.1.3

- `init --template fullstack` declares its pages as a site
  (`Pages.site` and `Pages.under`, in a module of their own) instead of
  `JasprModule(app:)`, serves the stylesheet from `/static/` and names
  `grund_jaspr: ^0.2.0`. A project generated by this version requires
  `grund_jaspr` 0.2.0, so publish `grund_jaspr-v0.2.0` before `grund_cli`.

## 0.1.2

- `init --template fullstack` scaffolds server-rendered Jaspr pages with
  cookie sessions (`grund_jaspr`, `grund_auth`), a sign-in form, a
  stylesheet in `web/` and tests; `--template api` (the default) is the
  previous scaffold.
- `init --template api` names `grund_http: ^0.2.0` (it named `^0.1.0`).
- `dev` reloads open pages: it serves server-sent events on a loopback
  port, passes the URL in `GRUND_LIVE_RELOAD_URL` and sends `reload` after
  every reload with a successful reassemble and once a started or
  restarted application serves (`grund_jaspr` adds the listening script to
  its pages).

## 0.1.1

- `init` scaffolds a `test/` directory with a smoke test and the `test` dev dependency.

## 0.1.0

Initial release.

- `grund gen` and `gen --watch`: write the generated file set
  (`X.g.dart` per source library) of the module and `@Api` constructs,
  only the files that changed, and nothing while the sources have problems;
  stale generated files are deleted, and a file without the generator's
  header is never overwritten or deleted.
- `grund dev`: runs the application and hot reloads it on every change,
  restarting it when a change of shape needs it; it prints what a reload
  added to and removed from what the application serves (for the HTTP
  server `+ GET /hello/bye`).
- `grund init`: scaffolds a new application (`App`, `@Module`, `@Api`,
  `HttpModule`, `IoAdapterModule`).
- `GrundCli` and `GenerationSession` for tools with constructs of their own.
- A source library with an unresolved `import`, `export` or `part` is a
  problem (`unresolved_uri`): `gen` writes and deletes nothing, exits with 1,
  instead of deleting the generated files.
- `gen` rewrites the generated files once after a change of the resolved
  `dart_style` release; the content is the same.
- A `@Module` in a part file is a `module_in_part` problem instead of an
  unreachable output file.
